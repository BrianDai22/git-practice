# Building Before Everything Is Certain

[The New Methodology — Martin Fowler](https://www.martinfowler.com/articles/newMethodology.html)

What I found interesting about this article is how Fowler treats uncertainty as an expected part of developing software. Requirements change, and people often need to use an actual version of a product before they understand what they want. That connects to an idea I find meaningful beyond software engineering. It is easy to keep preparing because preparation feels productive, even when it becomes a way of avoiding the discomfort of starting. A detailed plan can give me confidence, but some questions only become answerable once there is something real to test.

I think becoming comfortable with uncertainty takes practice. If I wait until I feel completely ready to build something, I could end up waiting for information that building it would have given me. Fowler’s discussion of short iterations gives that idea a practical form. I can start with a small, working version and use feedback to decide what comes next. There is still a chance that my first approach is wrong, and I think accepting that is part of becoming a better developer. What appeals to me is the possibility of building confidence through experience while still having unanswered questions.

I really liked the point about uncertainty being something developers should expect rather than avoid. The idea of building a small version first and learning from real feedback feels especially important because it turns uncertainty into something useful instead of something that prevents progress. I also think that mindset applies well beyond software engineering, since a lot of learning comes from actually starting before everything is fully figured out. - Mihir Ganesan
